## Roadmap requirements and acceptance criteria

Roadmap M1.2 requires versioned PostgreSQL migrations and durable assignment/event
storage aligned with the event contract, including authority reference, causality,
idempotency, and workflow metadata. Technical acceptance will require isolated
schema creation and migration; repeat/idempotent migration; rejection of checksum
drift; atomic state-plus-event transitions; rejection of illegal and duplicate
transitions; exact idempotency replay semantics; and persistence across reconnect.

The event contract is proposed, not a delegated authority service. This task may
persist authority references but must not claim to validate grants. It does not
implement M1.3 processor, M1.4 scheduling, worker execution, independent result
verification, dashboard, or notifications.

## Implementation and verification results

Implemented explicit checksum-pinned SQL migration support and a contract-aligned
PostgreSQL schema. `PostgresLedger` now requires explicit prior migration rather
than running DDL in its constructor. Assignment rows retain authority, objective,
contract, occupant, workflow and correlation metadata. `rv.event.v1` records actor,
authority, correlation, causation, idempotency, privacy domain, payload schema,
and payload. State change and event append remain one transaction. Reused
idempotency keys compare semantic input and reject conflicts. A caller-supplied
`verified` flag remains an untrusted claim; independent verification is not
implemented by this milestone.

progress. The temporary cluster and schemas were removed. The first runner test
exposed tuple-row handling; corrected with a dict row factory. A second run used
SQL_ASCII and returned byte-valued text; the disposable test cluster was corrected
to UTF-8 and all integration tests passed. Neither failed run used or altered the
commissioned `riverview_dev` schema.
