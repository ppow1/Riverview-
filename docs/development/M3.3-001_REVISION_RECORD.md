# RV-M3.3-001 — First end-to-end unattended demonstration

**Status:** BLOCKED — safe live execution preconditions are absent
**Roadmap cursor:** M3.3 remains the earliest unaccepted step. This checkpoint does not accept or waive it.
**Environment:** Camrui; shared database `riverview` / `riverview_dev`
**M3.2 dependency:** technical commissioning evidence at source `0fd10357ccdf2c9a0c87ba4a6f41e37ecff33ce9`; M3.2 full DoD remains open.

## Required proof

Roadmap M3.3 requires reproducible Camrui evidence for authorized concurrent
assignments, worker execution, independent verification, restart/recovery,
dashboard and notification. It explicitly makes this the first meaningful
runtime milestone. Tests or scripts alone cannot pass it.

## Preflight findings

The following findings describe the original M3.3 preflight; the current
implementation delta is recorded in the dated follow-up below.

1. The live shared ledger has one previously completed M3.1 worker assignment;
   it does not establish concurrent unattended work. Existing M2 tests verify
   concurrency and recovery only in isolated PostgreSQL schemas.
2. `PostgresWorkerAdapter` checks that a worker's free-form `scope_ref` string
   equals an assignment's `authority_ref`. The worker contract explicitly says
   the registration/control-plane operation is trusted and does not validate
   that reference against a durable Steward grant. No live grant service is
   connected to assignment creation or worker dispatch.
3. `ContinuousWorker` defaults to `UnavailableKnowledgeProvider`. The only
   packaged v1 provider is a test mock. A real source-backed institutional
   provider is not available in the deployed runtime. The fail-closed worker
   therefore cannot claim verified grounding/preflight from that missing
   provider.
4. The shared application DB role owns the schema. A library-level authorization
   check alone cannot prevent a service using that same role from inserting
   grants or assignments directly.

These are implementation/security boundaries, not SSH or operator convenience
issues. No shared assignments, workers, grants, credentials, or service state
were modified to manufacture the demonstration. The previous M3.1 live worker
evidence and M3.2 notification commissioning remain intact.

## Resolution path

- Implement M4.1 institutional identities and exact grants with a database
  privilege boundary; connect verified grants to assignment creation and worker
  registration/claim before shared assignments are authorized.
- Implement or integrate a real source-backed knowledge provider and bind its
  version/hash evidence to the exact deterministic work contract. No missing,
  mocked, or unverified retrieval may authorize an action.
- Resume M3.3 with two explicitly authorized concurrent assignments, distinct
  real workers, durable artifacts and independent verifiers; exercise restart,
  recovery, dashboard and notification against the same live run.

M3.3 remains IN PROGRESS and no milestone acceptance is claimed.
