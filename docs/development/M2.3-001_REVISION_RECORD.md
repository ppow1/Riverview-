## Intake and authoritative scope

Roadmap M2.3 requires retry/reconciliation policy, fenced attempts, restart
behavior, and explicit external-effect uncertainty handling. Its PASS criterion
is that forced process/worker interruption does not lose assignments or blindly
duplicate effects and that recovery outcome is auditable. M2.2 is the technical
predecessor. PR #9 and PR #10 remain open and CI-green; neither has merge
authorization. Work is isolated on a short-lived branch based on PR #10's exact
head, with a proposed M2.3 PR targeting PR #10 to preserve reviewable milestone
boundaries. No remote branch history is rewritten.

## Design

Persist a worker execution intent before calling an action. The built-in local
deterministic action is retry-safe; custom actions default to external-uncertain.
Legacy running work with no intent is treated as uncertain. An expiry
reconciliation transaction locks only the affected assignment and lease,
records one decision per assignment/generation, and appends causal state events
atomically. Durable results advance to independent verification; declared
retry-safe incomplete work is fenced then requeued; uncertain outcomes wait in
`awaiting_steward`. The CME and unrelated assignments remain schedulable.

## Acceptance evidence required

- Actual child process termination after a durable intent and recovery after
  lease expiry.
- External-effect test commits one isolated effect, kills its worker, confirms
  `awaiting_steward`, and proves the effect is not blindly duplicated while a
  separate assignment progresses.
- Retry-safe work requeues only under a higher lease generation.
- A committed result survives interruption and advances to
  `awaiting_verification` without recomputation.
- Previously completed/independently verified work remains terminal.
- Full applicable suite, process graph validation/synchronization, revision
  checker, and remote CI pass; all PostgreSQL schemas are uniquely named and
  dropped by fixtures.
