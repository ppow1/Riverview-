## Intake and defect analysis

Continue RV-M1.3-001 from its isolated implementation; do not re-run or replace
the M1.1/M1.2 work. The first review identified an event-ordering race: PostgreSQL
identity values are allocated inside transactions but are not commit-order
identifiers. If sequence N remains uncommitted while N+1 commits, a cursor can
observe N+1 and permanently skip N. The worker also lacked exact startup migration
verification, did not reconnect its leader session after PostgreSQL session loss,
and had no independently commissioned systemd unit or deployment recovery path.

## Design decisions

- Serialize `PostgresLedger` event inserts through transaction commit with a
  transaction-scoped advisory lock acquired before identity allocation. This is
  a correctness guard for the current global cursor; its throughput cost is
  recorded for M1.4 review.
- Keep cursor migration 0002 separate from M1.2 migration 0001. The service
  checks both source checksums and the cursor table before processing; it never
  applies DDL automatically.
- Deploy M1.3 through a distinct `/opt/riverview-event-processor` root-owned
  release link and `riverview-event-processor.service`. Do not replace the
  `/opt/riverview-core` M1.1 link or `riverview-baseline.service`.
- Reuse the established systemd `LoadCredential` model and validated copy into a
  private runtime mode-0600 libpq passfile. The runner rejects ambient libpq
  credential overrides and password-bearing DSNs.
- Reacquire the PostgreSQL advisory lease after connection loss. The worker
  rechecks migration history on reconnect and leaves its durable cursor intact.
- Recovery restores only the prior M1.3 unit/link and enabled/running state. It
  retains migration 0002, cursor history, backups and the M1.1 runtime.

## Acceptance and verification

Required commissioning checks: full backup and restore drill; checksum and
schema preflight; migration apply/rerun and ownership verification; systemd
credential path/mode; unattended assignment progression; event causality and
monotonic cursor; process restart; database-session loss and lease reacquisition;
preserved M1.1 readiness; service rollback and recovery. Isolated tests cover
event sequence commit order, idempotent crash replay, schema checksum drift,
credential delivery, and reconnect behavior.

Evidence paths and actual outcomes are added after each operation. Scoped M1.3
technical commissioning is evaluated separately from the full component DoD.
The M3.1 dashboard and later autonomy obligations remain open and are not
waived by this task.
