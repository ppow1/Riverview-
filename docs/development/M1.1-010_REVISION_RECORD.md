## Requirement and evidence

The installed M1.1 systemd service must consume the existing credential securely
and establish the read-only database baseline. Deployment at source commit
`a25aa71b08f877b12445cb71508a480b06d6af7d` passed storage validation after
RV-M1.1-009 but exited during libpq authentication. The journal warning said
that the systemd credential file at `/run/credentials/riverview-baseline.service/pgpass`
had group/world access; its actual mode was 0440. libpq requires 0600 or less.

## Design and implementation

Preserve the source delivery contract: fixed PID 1 credential directory, root
ownership, directory 0550, file 0440, effective service readability, and no
symlink traversal. Add a systemd-managed `/run/riverview-credentials` runtime
directory, owned by `riverview` and mode 0700. After source validation, copy
without logging through `O_NOFOLLOW` and `O_EXCL` descriptors to `pgpass` mode
0600, require expected runtime ownership and regular-file type, then provide
only that private copy to Psycopg. A pre-existing destination and symlink fail
closed. systemd removes the runtime directory after the oneshot stops. No
credential value enters source, arguments, reports, or logs.
