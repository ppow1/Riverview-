## Intake, design and acceptance

The deployed M1.1 service returned UNSAFE_PATH, step_id=storage, source
3d7e58fc19ae38b6fd378fd0f0421ebb36fdb266. The assignment authorizes project-
scoped administrative operations and requires a root-owned helper protected
from the Codex account. Acceptance requires exact cause evidence; separate
strict state/credential predicates; a fixed-operation broker; exact package
provenance; rejection of arbitrary inputs; non-privileged regression coverage;
root-owned installation and policy; package rebuild; live baseline/acceptance;
recovery verification; and truthful M1.1 DoD status.

The deployed sandbox was reproduced with systemd-run and the exact unit
security properties. /var/lib/riverview is riverview:riverview 0700 and
passes in service context. PID 1's credential directory is root:root 0550 and
its pgpass is root:root 0440; both are readable/traversable by riverview. The
prior code checked the directory with a function that requires runtime UID
ownership, and reported that parent rejection as storage. Root cause: incorrect
ownership contract reuse, not symlink policy or state ownership.

Design decision: preserve all private-state checks. Validate systemd credential
delivery separately at the fixed unit credential path, requiring stable
non-symlink resolution, root ownership, exact read-only metadata, regular
nonempty file and effective service access. The root-owned broker only accepts
registered package identifiers, fixed service operations, a sanitized report,
acceptance capture, and constrained rollback record identifiers. Root policy
pins exact package digest and source commit. It rejects arbitrary
paths/commands, unsafe tar members and mutable/incorrect release content; only
the exact hash-verified archive is extracted root-owned, then its fixed
installer is invoked. New release digests need an explicitly reviewed
root-policy update. No user checkout script is run as root.
