## Current backend capability inventory not exposed in V2

The current Dashboard already owns bounded read-only projections for individual objectives, assignments, assignment details, event cursor, worker/lease health, CME attention, notifications, and aggregate system/CME status. V2 currently exposes only aggregate resource-status integration, authenticated Grace conversation, and this increment's objective/assignment summary. Those contracts are not a replacement for Estate's historical file-based compute or Mission Control lanes. Privileged proposal creation, cancellation, notifications receipt acknowledgment, and other write APIs are not presented as V2 capabilities.

Additional current backend capabilities not connected to either the current V2 workspace or the inspected historical Office presentation/data contracts include per-assignment attempt and verifier summaries (`GET /api/v1/assignments/<id>`), privacy-filtered event chronology (`GET /api/v1/events`), worker/lease heartbeat freshness (`GET /api/v1/workers`), CME attention/recovery summaries (`GET /api/v1/attention`), durable visual notifications and pending decision state (`GET /api/v1/notifications`), and the versioned aggregate deployment/schema/CME view (`GET /api/v1/status`). The current V1 Dashboard implementation owns these APIs and may surface parts of them; the claim here is specifically that V2 has not integrated those views and the historical Estate artifacts are a separate data owner. Further V2 panels should reuse the existing navigation and authenticated context rather than recreate Estate's old tab set.

## Phase 1 integration contract

The Work view makes only same-origin `GET /api/v1/auth/session`, then `GET /api/v1/objectives?limit=25` and `GET /api/v1/assignments?limit=25`; it requires the Dashboard session before requesting either projection. It does not send a bearer token, request body, or mutating method. The view is manually refreshed and does not poll. It displays IDs, lifecycle status, assignment link/state, verifier decision, workflow/step, owner label, last persisted event label, and persisted time. It does not display objective text, criteria, artifact location/digest, or event payload. Browser fetch time is not represented as backend freshness.

The existing V2 layout/navigation/center workspace remains the UX baseline. The Work view adds a live read-only panel ahead of the existing clearly labeled fixture examples. No historical Estate code or generated runtime data is copied into the V2 runtime. No production grant, source backend, database, model host, V1 route, or service is changed.

## Verification and limits

Source contracts were checked against the cited current backend commit and historical Estate main commit. Offline browser-runtime tests validate auth gating, same-origin GET-only calls, redacted projection, unavailable/unauthorized states, and no polling or writes. They do not establish live authenticated data visibility or production acceptance. Historical GPU inventory contents, current live Estate runtime, and V2 Windows Chrome acceptance are **UNVERIFIED**.
